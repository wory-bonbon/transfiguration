## 0. 要約

RAW 版は幾何の長さを**基音の周波数**へ写像した。本拡張は同じ原理を**音色（倍音構成）**へ延長する。

> 各 voice の部分音の周波数比率を、その瞬間の多面体自身の長さの比から導出する。
> 基音だけでなくスペクトル全体が幾何の写像になる。

ガラス・ベル系の音の正体は「非整数比で並ぶ部分音の集合」である。多面体のクラス長比は元来非整数比なので、幾何比率をそのまま部分音比率に使うことで、外部音源もプリセットも使わずにガラス的な質感（v1.1 §9.1 の glass / crystal resonance 方向）へ近づく。

これは音を「足す」のではなく、既存の写像を音色次元へ拡張するものであり、**RAW の哲学（v1.1 §3.1、CLAUDE.md の RAW 定義）に完全準拠する**。スケール量子化・録音素材・サンプルは引き続き使用しない。

### 自己相似方式を採る理由

```text
f_i = f0 · L_ref / L_i        ← v1.1 §4.2 の周波数式
r   = L_i / L_k

f_i · r = f0 · L_ref / L_k = f_k
```

**「クラス長比を部分音比率にする」と、第1部分音は必ず別クラスの基音に一致する。** これだけでは新しいスペクトルは生まれず、既に鳴っている周波数の重み付けが変わるにすぎない。

そこで自己相似 `{ r, r² }` を採る。

```text
f_i · r   = f_k                          既存の基音を強調する
f_i · r²  = f0 · L_ref · L_i / L_k²      既存集合に無い新しい周波数
```

比率は依然として多面体自身の長さのみから導かれるため、RAW 原則は維持される。

## 3. 部分音の導出規則

### 3.1 自己相似方式

各 voice は（クラス c、モード m ∈ {1, 2}、自長 L）の3つ組を持つ。F2 のとおり、この対応はモードごとに独立である。

```text
voices[2k]    :  c = SND_CLS[sndOrd[k]] ,  m = 1 ,  L = c.len
voices[2k+1]  :  c = SND_CLS[sndOrd2[k]],  m = 2 ,  L = c.len2
```

候補プールは**モードごとに分離する**。第1モード voice が第2モード長を参照すると、順序が独立に動く2系統（F2）が結合し、フリッカーの原因になる。

```text
P₁ = { SND_CLS[j].len  | j = 0..3 , weight_j > 0 }
P₂ = { SND_CLS[j].len2 | j = 0..3 , weight_j > 0 }
```

voice i（自長 L_i、モード m_i）に対して：

```text
r_i = min { L_i / L  |  L ∈ P_{m_i} ,  ε·L_i ≤ L  ,  L_i / L > 1 + ρ_min }

      ε     = 0.05     相対しきい値（§10-6）
      ρ_min = 1e-9     自クラス・同長クラスの除外（下記）

部分音周波数 :  f_i · r_i  ,  f_i · r_i²
```

1. `r_i` は 1 より大きい比率のうち**最小のもの**。すなわち自分より1段だけ短い代表長との比
2. 候補が存在しない場合、その voice は**部分音を持たない**（部分音ゲインを 0 へフェード）。最短の代表長を担当する voice は常にこれに該当する
3. `ε = 0.05` により `r ≤ 20`、`r² ≤ 400` に自動的に収まる。上限側は §3.3 のゲートが処理する
4. 比率は毎更新で長さから導出されるため、形態変化に伴い部分音も連続的に動く（追加の補間処理は不要。25Hz パス＋Web Audio automation で v1.1 §12 のまま）

#### 実装上の等価変形

`f = f0·L_ref/L` より `L_i / L_k = f_k / f_i` である。したがって比率探索は
**「自分より高い最寄りの周波数を選ぶ」**ことと同値で、除算が 1 回で済む。

```text
候補条件:  f_i·(1 + ρ_min)  <  f_k  ≤  f_i / ε
```

#### なぜ `weight > 0` が必要か（v0.2 からの訂正）

v0.2 は「退化クラスの `len` は 0 付近まで追随してから凍結するので、ε 条件だけで排除できる」としていた。**これは第1モードにしか当てはまらない。**

第2モード長 `len2` は面の apothem / apex→辺中点距離である。辺の長さが 0 へ潰れても apothem は 0 にならない。`accAdd` の辺重み `ew` が 0 になって集計母集団から外れるため、`len2` は**「無音なのに通常の大きさのまま」凍結**する（F8）。実測では Icosahedron のクラス B が `len = 0.000028` / `len2 = 0.003698` / `weight = 0` となっており、長さだけを見る ε 条件ではこれを排除できない。

したがってプールへの参加条件として `weight > 0` を課す。

#### なぜ `ρ_min` が必要か（v0.3 新設）

`sndApply` は基音を `f = SND_F0*(SND_LREF/L)` と計算し、プール側は `SND_F0*SND_LREF/len` と計算する。**結合順が違うため、同じクラスでも最終 1ulp がずれる。**

素の `f_k > f_i` を使うと、自クラスの pool 値が `f_i` の 1ulp 上に来た場合に `r = 1 + 1e-16` となり、これが「最小の候補」として常に勝ってしまう。結果、**本来の候補が覆い隠されて部分音が消える**。

実測（Truncated Dodecahedron）で次が起きていた。

```text
voice 0 (クラス C) : 期待 cand=A / r=φ    → 実際 cand=C / r=1  （φ の部分音が消失）
voice 2 (クラス B) : 期待 cand=D / r=√3   → 実際 cand=B / r=1  （√3 の部分音が消失）
```

`ρ_min = 1e-9` は ULP 由来の擬似候補（`r−1 ≈ 1e-16`）だけを落とし、幾何的に意味のある近接候補は残す。同時に、ti / td のように `L_A = L_B` が厳密に成立する状態で §3.1 の狭義不等式 `L_k < L_i` を正しく実現する。

##### 第2モードの比率の正体

- **SSD = √5（r² = 5 ちょうど）**
  apex 高さ `h = σ·R_f`、σ = φ、五角形は `R_f = a/(2 sin36°)`、apothem = `a/(2 tan36°)`。
  `h / apothem = φ · tan36°/sin36° = φ / cos36° = φ / (φ/2) = 2`（厳密に 2）。
  よって `C2 = apothem·√(1+2²) = apothem·√5`、`A2 = apothem` となり `r = √5`。
- **TD = √(√3 / tan18°) = 2.308825**（`r² = √3/tan18° = 5.330674`）。十角形の apothem と三角形の apothem の比。
- **TI = √(√3 · tan36°) = 1.121788**（`r² = √3·tan36° = 1.258409`）。
  クラス B の `len2` は六角形 apothem と五角形 apothem の**幾何平均**（寄与が 60 本ずつ）になるため、A2 / B2 / D2 が等比数列を成し、r が2箇所で一致する。この重み構造は TD の実測値 `B.len2 = 0.227704 = √(0.525731 × 0.098623)` で裏取り済み。

##### 読み取れること

- **第1部分音は必ず既存の基音に重なる**（§0）。新しい周波数を作るのは `r²` の側である
- **`r²` が整数になる状態がある。** Ico / TD 第1モードの `r² = 3`、SSD 第2モードの `r² = 5`。いずれも √3、√5 の二乗という幾何の帰結であり、欠陥ではない。ただし v0.1 §3.2 の「整数比にならないこと」という主張は誤りなので撤回する。部分音の集合 `{1, √5, 5}` は全体としては非調和である
- **第2モードの r は第1モードより大きい傾向がある。** 面の apothem は面の大きさで大きく変わるため。TD 第2モードでは `r²` の部分音が 3183 Hz に達し、`sndGate` の高域ロールオフ（3000 Hz 開始）に入りはじめる
- **最短の代表長を担当する voice は常に部分音を持たない。** 4クラスすべてが鳴る状態（ti / td / id）では 8 voice 中 2 voice が該当する

### 3.3 範囲外の扱い

部分音周波数にも、基音とまったく同じ **`sndGate(f)`** を適用する（F4）。

```text
f ≤ 26 Hz          → gain 0
26 – 45 Hz         → smoothstep でフェードイン
45 – 3000 Hz       → gain 1
3000 – 6000 Hz     → smoothstep でフェードアウト
f ≥ 6000 Hz        → gain 0
```

clamp は行わない（v1.1 §4.2）。`r² ≤ 400` により最悪ケースでも `f · r²` は有限だが、多くの状態で 6 kHz を超えて自動的に無音になる。これは意図した挙動である。

非有限値は v1.1 §18.1 の防御をそのまま適用し、`Number.isFinite()` 検査を通さない値を AudioParam へ渡さない。周波数が無効な場合は直前の有効値を保持し、ゲインのみ 0 へフェードする（`sndApply()` と同じ規約）。

### 3.4 候補条件のまとめ（v0.3 新設）

3 つの門はそれぞれ別の失敗を防いでいる。ひとつでも欠けると実測で不具合が出る。

| 門 | 式 | 防ぐもの | 欠けたときの実測症状 |
|---|---|---|---|
| weight | `weight_k > 0` | 無音クラスの凍結 `len2` | 鳴っていないクラス由来の部分音が出る |
| ε（上限） | `L_k ≥ ε·L_i` | 退化フェード中の比率発散 | `r` が発散し超高域の部分音が出る |
| ρ_min（下限） | `L_i/L_k > 1 + 1e-9` | 自クラス・同長クラスの ULP 混入 | 本来の候補が覆い隠され部分音が消える（TD の φ・√3） |

さらに、門を通ったあとのゲイン側で 2 段のフェードをかける（§4 / §6.2）。

```text
w_c = smoothstep( weight_cand / 0.02 )   候補クラスの退化フェード
w_r = smoothstep( (r − 1) / δ )          r→1 のコヒーレント加算フェード
```

`w_c` はプールからの離脱を無音側で吸収するためのものである。weight は 0 へなめらかに落ちてから厳密に 0 になるので、離脱の瞬間には部分音が既に聞こえていない。これにより離脱が周波数ジャンプとして現れない（v1.1 §18.1 の方針に一致）。

## 4. 部分音のゲイン設計

```text
a_k  = ρ^k · w_r · w_c · sndGate(f_i · r^k)     部分音の実効相対振幅（k = 1, 2）
norm = 1 / √( 1 + a_1² + a_2² )                voice ごとのパワー和正規化

  基音   :  g_0 · norm
  部分音 :  g_0 · a_k · norm

ρ    = ρ_base + ρ_sig · (σ / φ)       σ は SEGS 上で 0 → φ を動く
       ρ_base = 0.35 , ρ_sig = 0.65 , ρ 上限 1.0   （Phase M3）

w_r  = smoothstep((r − 1)/δ)          δ = 0.05（§6.2）
w_c  = smoothstep(weight_cand/0.02)   候補クラスの退化フェード（§3.4）
```

`g_0` は既存実装の voice ゲイン（`SND_GBASE · weight · SND_M2^(mode-1) · sndGate(f_i)`）をそのまま使う。

1. σ = 0（非星形）では ρ = 0.35。部分音は基音の −9 dB に収まり、RAW v1 の印象を大きく変えない
2. σ 増加で部分音が立ち上がる。v1.1 §6.2「星形化で高域・倍音が増える」を、フィルタではなく実部分音で実現する。**既存の固定フィルタ（lowpass 5000 Hz / Q 0.7）は変更しない**。modal モードにおける高域の増減は ρ_sig のみで制御する（§10-4 確定）
3. **正規化はパワー和で行う。** 異周波数の正弦波は非コヒーレントに加算されるため、振幅和 `1/(1+ρ+ρ²)` で割ると σ = 0 で約 −3.4 dB 下がり、AC-M1 と衝突する。パワー和なら σ = 0 で −0.55 dB、ρ 上限 0.6 でも −1.7 dB に収まる
4. 最終的なクリップ防止は既存の Compressor（threshold −12 dB / ratio 12）が担う。v1.1 §11 のグラフは変更しない

5. **`norm` は voice ごとの実効値で計算する。** v0.2 が書いた `1/√(1+ρ²+ρ⁴)` は両部分音が満振幅のときの特例であり、候補なし・帯域外・`r → 1` の voice では `a_k = 0` となって自動的に `norm = 1` になる。固定式を使うと、部分音を持たない voice まで一律に減衰してしまう
6. **`norm` は filter の後段に置いた専用 GainNode（`v.norm`）が担う。** 基音のゲインは RAW の `sndApply()` が握っているため、同じ AudioParam へ二重に自動化を積まずに済む（§5）

### ρ 上限が 1.0 である理由（Phase M3）

正規化後の部分音ゲインは `g_1 = ρ / √(1+ρ²+ρ⁴)`。その微分は

```text
d/dρ [ ρ · norm ] ∝ 1 − ρ⁴
```

に比例する。すなわち **ρ = 1 で最大となり、ρ > 1 では減少に転じて AC-M5（σ 掃引で部分音ゲインが単調増加）が壊れる。** 部分音2 も同様に `2ρ(1−ρ⁴)` で ρ = 1 が頂点。

したがって **1.0 は単調性の保証限界であり、同時に σ による音色変化を振れる最大点**でもある。M3 の方向（§10-12）がここまで振ることなので、上限を 0.6 から 1.0 へ引き上げた。

ρ = 1 では基音・部分音1・部分音2 の振幅が等しくなる。倍音がすべて同じ強さで並ぶ、鐘に近いスペクトルである。

### σ 連動の実効ゲイン（Phase M3 の値）

TD voice C（`r = φ`、両部分音が帯域内）での実効ゲイン。総パワーは σ に依らず 1 に保たれる。

| σ | ρ | 基音 | 部分音1 | 部分音2 |
|---|---|---|---|---|
| 0（凸） | 0.350 | −0.56 dB | −9.68 dB | −18.80 dB |
| φ/2 | 0.675 | −2.21 dB | −5.62 dB | −9.04 dB |
| φ（SSD） | 1.000 | −4.77 dB | −4.77 dB | −4.77 dB |

M2（ρ_sig = 0.25）との比較。

| | M2 の振れ幅 | M3 の振れ幅 |
|---|---|---|
| 部分音1 | 3.5 dB | 4.9 dB |
| **部分音2** | **8.2 dB** | **14.0 dB** |
| 基音 | −1.2 dB | −4.2 dB |

σ=0 の値は M2 から変えていない。**凸多面体の音は Phase M2 で承認された状態のまま**で、星形化側だけが伸びる。

星形化が進むにつれてエネルギーが基音から部分音へ移る。σ は幾何としても `len2`（apex→辺中点距離）を伸ばすため、ρ は同じ幾何変化の音色側の現れであって別系統の演出ではない。

## 5. Audio Graph の変更（Voice 内部のみ）

```text
[v1 RAW]   Osc → Gain → Filter ────────────┐
                                            ├→ Voice Mix → Compressor → Master Gain → Destination
[modal]    Osc(基音)   → g_0 ┐              │
           Osc(部分音1) → g_1 ├→ Filter → norm ┤（voice 内で合流）
           Osc(部分音2) → g_2 ┘              │
```

- 部分音 Oscillator は既存の voice Filter の**前段**で合流させる。安全ロールオフ（lowpass 5000 Hz）を部分音にも効かせるため
- Filter の**後段**にパワー和正規化用の GainNode（`v.norm`）を挿む。基音と部分音の両方へ一度だけ効く（§4-6）
- 外側のグラフ（Mix 以降）は v1.1 §11 から**一切変更しない**。StereoPanner（P2）の挿入位置も v1.1 のまま
- 部分音ノードは `?timbre=raw` **でないとき**に生成する（既定 = modal。AC-M1）
- v1.1 §4.1 のとおり、AudioNode をフレームごとに生成・破棄しない。初期化時に確保し、以後はパラメータのみ更新する

## 6. Voice tracking の拡張

v1.1 §24 の原則を部分音へも適用する。自己相似方式では voice ごとの独立変数が `r` ひとつになるため、v0.1 §6-1 が要求した「部分音 index の入替禁止」は自動的に満たされる。

### 6.1 順序交差点の連続性

`r` が不連続になりうるのは、**自分より短かったクラスが自分を追い越す瞬間**のみである。この瞬間は定義上 `L_k = L_i`、すなわち `r = 1` であり、部分音は基音に一致している。したがって周波数は連続である。

Dod → SSD 遷移（AC-M4）の実際。**中間点は実測で確認済み。**

```text
Dodecahedron    L_A = 0.7639 > L_C = 0.6498
                voice A : cand=C , r = 1.1756        voice C : 候補なし

交差点           L_A = L_C
                voice A : r → 1（部分音が基音へ収束、w_r → 0）
                voice C : r → 1（部分音が基音から分離開始）

遷移途中（実測） L_C = 1.0906 > L_A = 0.7639
                voice C : cand=A , r = 1.4277        voice A : 候補なし

SSD             L_C = 1.2361 > L_A = 0.7639
                voice C : cand=A , r = φ = 1.6180    voice A : 候補なし
```

部分音は voice A から voice C へ「乗り移る」が、その受け渡しは常に `r = 1`（＝基音そのもの）の位置で起こる。実測の中間点 `r = 1.4277` は交差点の 1.0 と SSD の 1.618 の間にあり、連続に移動していることを裏付けている。

### 6.2 `r → 1` フェード（必須）

`r ≈ 1` では基音・第1部分音・第2部分音が同一周波数へ重なり、**コヒーレント加算**になる。振幅が `1 + ρ + ρ²` 倍（ρ = 0.35 で約 +2.8 dB）に膨らみ、v1.1 §17 の「sudden gain jump 防止」と衝突する。

```text
w_r = smoothstep( (r − 1) / δ )        δ = 0.05（§10-6）

r ≤ 1.00  → w_r = 0
r ≥ 1.05  → w_r = 1
```

これにより、候補集合への出入り（部分音の出現・消滅）も自動的にゲインフェードになる。

**`w_r` は Phase M1 で実装した**（v0.2 §11 では M2 の項目だったが前倒し）。ti / td は A = B = C が同一長のため `r ≈ 1` となり、この guard が無いと 25Hz でフリッカーして M1 の聴感評価そのものが成立しないため。

### 6.3 その他

1. 基音の voice tracking 挙動は変更しない
2. `r` の平滑化は不要。25Hz パスで再計算された `r` から算出した部分音周波数を、基音と同じ `setTargetAtTime(·, t, SND_TC_F)` へ渡す
3. 部分音ゲインも基音と同じ `SND_TC_G` を使う

## 8. モード切替

1. **デフォルト（パラメータなし）は modal。** これが本作の音である
2. **`?timbre=raw` を付けたときだけ RAW v1 の音**になる。部分音ノードを生成せず、実行経路も RAW と同一（AC-M1）
3. パラメータ解析は `sndInit()` の冒頭で1回だけ行い、以後は定数として扱う（実行中の切替は行わない）
4. 判定は case-sensitive。`?timbre=raw` のみを RAW として受け付ける。`?timbre=modal` は明示指定として通るが既定と同じ挙動（既存の共有リンクを壊さないため）
5. 例外時（`location` 参照不可など）は既定側の modal へ倒す
6. UI トグルは**追加しない**（§11.1-1 で確定クローズ）

### `?timbre=raw` を残した判断（追補）

**残す。** 追加コストは `mtResolve()` の正規表現 1 行のみである。

分岐そのものを廃止するには `MT.on` の門（seam 2/4・3/4・4/4）を消して部分音を常時生成する形へ書き換える必要があり、**残すより変更量が多い**。加えて、

- Phase M2 / M3 の聴感調整で RAW との A/B 比較が要る
- 不具合切り分け時に「modal 起因か RAW 起因か」を URL だけで判定できる
- CLAUDE.md が求める RAW との比較可能性を、タグ `raw-v1` の checkout なしで満たせる

以上より、廃止は合理性がないと判断した。

## 13. 運用メモ（v0.3 新設）

### `file://` で直接開かないこと

ローカルの HTML ファイルをブラウザへドラッグして開くと、次のエラーが出て three.js が読み込めない。

```text
Unsafe attempt to load URL https://cdnjs.cloudflare.com/... from frame with URL file:///...
'file:' URLs are treated as unique security origins.
```

**原因は本拡張ではなく、RAW 由来の既存コードである。**

```text
index.html:60  <script src="https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js">
index.html:63  document.write('<script src="https://cdn.jsdelivr.net/npm/three@0.128.0/...">')
```

この 2 行は Phase 0 の visual baseline（`3363847`）から存在する。WebKit は `file:` を unique origin として扱うため、https の外部スクリプトを拒否する。

**GitHub Pages（https）では発生しない。** 公開中の RAW v1 が正常に動作していることが実証になっている。同一スキーム間の通常の cross-origin script 読み込みであり、CORS 上の問題はない。

ローカル検証時は HTTP で配信する。

```sh
python3 -m http.server 8000
# → http://localhost:8000/index.html?timbre=modal
```

録画用に別マシンで再生する場合も、Pages の URL かローカル HTTP サーバを使うこと。

## 14. 付録 — v0.1 → v0.2 の変更履歴

| # | 変更点 | 理由 |
|---|---|---|
| 1 | AC-M2 の φ の担い手を SSD voice A → voice C へ訂正 | `L_C > L_A` であり、比率は長い側の voice に付く |
| 2 | 候補条件を「ゲイン > 0」から `L_k ≥ ε·L_i` へ変更 | 退化フェード中に比率が発散する（v0.3 で weight 条件を復活させ、両方を課す形に落ち着いた） |
| 3 | 部分音比率を独立2値から自己相似 `{r, r²}` へ変更 | `f_i·(L_i/L_k) = f_k` が恒等的に成立し、新しいスペクトルを生まないため |
| 4 | 「第2モード係数」は存在しないと判明。候補プールをモード別に分離 | 実装は係数ではなく実測長 `len2` を使う |
| 5 | 帯域処理を既存 `sndGate()` の再利用に変更 | 実装済みのゲートがある |
| 6 | `r → 1` 近傍の部分音フェードを必須化 | コヒーレント加算で +2.8 dB の膨らみ |
| 7 | 音量正規化をパワー和方式として明示 | 振幅和では σ=0 で −3.4 dB 下がる |
| 8 | voice ↔ クラス対応が偶数 / 奇数で独立であることを明記 | 実装は `sndOrd` / `sndOrd2` の2系統 |
| 9 | §10 の再編 | 実装調査により 1/2/3 が確定、4 が再定義された |
| 10 | 実装実測値の付録を新設 | Phase M で参照可能にする |
